# 目标与范围

## 目标
从运行中的通达信 PC 客户端提取全市场行情数据，要求：
- **覆盖 L1 与 L2**：最新价、分时、K 线、盘口（L1），以及逐笔成交、十档委托队列（L2）；
- **不限代码数**：全市场覆盖，不受客户端 UI 限制；
- **不限频率**：绕过客户端内部可能存在的软件节流；
- **可选的独立直连**：最终目标是普通脚本直连服务器获取数据，不依赖客户端进程。

## 技术路线

与同花顺项目类似，有三大可行路线：

### 路线 A：读客户端内存（被动读）
通达信客户端运行时已在内存中持有实时行情数据（否则 UI 无法秒出）。通过 Frida 注入或内存扫描直接读取已解码的结构化数据。
- 优点：对服务器零负担，不需要理解网络协议；
- 缺点：仍依赖客户端运行，跨版本兼容性差。

### 路线 B：Hook 内部分发函数（中间路线）
通过 Frida hook DLL 导出函数（如 `TDataParse.dll` 的解析函数），截获解码后的数据。
- 优点：比裸内存更稳定，数据类型已知；
- 缺点：仍需注入，受客户端更新影响。

### 路线 C：独立 TCP 直连（最终目标）
完全复制客户端的网络协议——登录认证、建立 TCP 连接、解析二进制帧格式，用普通 Python/Go 脚本直接连接通达信服务器。
- 优点：零依赖，可无人值守运行；
- 缺点：需要完整逆向上层认证和底层帧协议，工作量最大。

**推荐路径**：先用路线 A/B 快速拿到内存中的参考数据（确认字段语义），再切换到路线 C 做独立实现。

## 与同花顺的关键差异

| 维度 | 同花顺 (THS) | 通达信 (TDX) |
|---|---|---|
| 主进程 | `hexin.exe` (UPX 壳) | `TdxW.exe` (无壳，VC++ 2010) |
| UI 框架 | Qt + CEF + HTMLayout | MFC + CEF |
| 脚本接口 | `python35.dll` + `ths_api` + Lua 5.1 | 当前安装未发现此前推断的 `TPyth.dll` |
| 网络层 | IOCP + `func_sdk_17.dll` | `TAsioComm.dll`（Boost.Asio？） |
| 认证体系 | verify3/Passport64 + HMAC-SHA256 | 待调查 |
| 服务端域名 | `10jqka.com.cn` / `thsi.cn` | `tdx.com.cn` 系列 |
| L2 数据 | `8901`/`9601` TCP 端口族 | 待调查 |

## 范围红线（责任边界）
- **只做个人研究和自用**：只读自己运行、自己登录的客户端数据；
- **不外传、不转售数据**；
- **不绕过付费鉴权**：不使用未授权的 L2 数据源或绕过 License 检查；
- **不打服务器**：不伪造/重放协议、不绕过鉴权去取无权数据；
- 普通 L1 行情本质是广播给所有免费用户的公开数据，个人自用属互操作性研究范畴。

## 交付物形态（默认）
- 按需查询的 Python 接口：传入任意代码列表（不限数量）→ 返回 `pandas.DataFrame` / dict；
- 可选：全市场快照轮询 / 实时流（socket 或 WebSocket）/ 落库 SQLite；
- 最终独立 TCP 直连客户端：零依赖运行，不需要通达信客户端进程。
