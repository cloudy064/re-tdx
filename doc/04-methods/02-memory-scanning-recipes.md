# 内存扫描套路

> 基于同花顺项目的经验，适配通达信（TdxW.exe，32位）。所有扫描策略需要在 TDX 实际运行时验证。

## 通用范围过滤
只扫可读写、单块 < 32~64MB 的区（排除超大映射，提速且避开无关大块）：
```js
var ranges = Process.enumerateRanges('rw-').filter(r => r.size < 64*1024*1024);
```

## 配方 1：按代码字符串找结构
- 目标：主证券表 / 订阅列表 / 代码索引。
- 模式：ASCII `600519`（命中订阅列表中的 `600519`）或 asciiZ。
- 方法：`Memory.scanSync` 搜索 UTF-8 或 ASCII 版本的股票代码。
- 注意：TDX 的代码格式可能与 THS 不同（如是否带市场前缀 `SH`/`SZ`，是否六位代码），应先从 UI 确认。

## 配方 2：按已知数值找行情记录（需参考值）
- 目标：定位价格和成交量。价格可能是 **float64** 或 **整数（分）×1000**。
- 方法：
  1. 从 UI 获取一支确定股票的当前价格（如 `600519` 的现价）；
  2. 分别用 `struct.pack('<d', price)`（f64）和 `struct.pack('<i', int(price*1000))`（整数） 扫描；
  3. 在命中结果附近搜索相邻字段（开/高/低/收/量），确认是否是行情记录。
- **坑**：噪声块（图表/指标/阶梯）会污染大窗口聚类。用**非整、辨识度高的值**作锚。

## 配方 3：锚定单值 + dump 邻域（看真实布局）
- 用脚本扫该 f64，对每个命中 dump ±N 字节 + 解出邻近所有 double（带相对偏移）。
- 这是判断"是紧凑记录 / 列式数组 / 图表缓冲 / 阶梯"的关键一步。

## 配方 4：跟指针链（一次会话内）
- 因缓冲会漂移，**扫描→读指针→解目标 必须在同一 attach 会话**完成，别跨脚本用旧地址。

## TDX 特有的可能内存布局

通达信可能使用与同花顺不同的数据结构：
- **可能的设计 A**：类似 THS，每个股票一个紧凑 struct（如 [code][name][open][high][low][close][volume]...）
- **可能的设计 B**：列式存储（一个大数组存所有代码，另外的数组存价格、量等）
- **可能的设计 C**：MFC CDocument/CDocTemplate 体系中的 C++ 对象数组
- **方法**：先用 IDA 分析 `TDataParse.dll` 和 `TBigData.dll` 的数据结构引用，确定字段偏移后再用内存扫描验证。
