## 不可退让的边界

- 最终 `tdx-tool.exe` 不依赖 Python 解释器、Python DLL 或 Python 包；
- 不允许子命令通过进程启动、管道或临时文件转发到旧 Python 脚本；
- 子命令只有在协议、解析、校验和输出均由 C++ 实现后才注册到帮助中；
- 旧脚本只作为已知协议的证据和回归对照，不是产品运行组件。

按进程名或 PID 输出父进程、线程、启动时间、WOW64、本地/全部模块以及 IPv4/IPv6
端点。`--baseline` 可直接报告进程、模块、连接的新增与消失。默认只列本地模块，
但会递归纳入目标的存活子进程并给出根 PID/树深；`--no-children` 可关闭。不注入、
不 attach、不读取进程内存或会话字段。`--watch-seconds/--interval-ms` 又把
连续采样压缩为首末帧、轻量汇总和真正变化事件，观察文件可继续作为基线。当前两个
真实 TdxW 实例已形成基线。随后又直接复用 `session-config` 的公开 endpoint_groups，
按地址+端口标注 section/名称/primary，当前安装为 6 组/69 个端点；不嵌入私密状态，
不做 DNS 猜测。下一步只需在用户触发登录、订阅、页面切换和重连时运行观察命令，
无需再写临时脚本。

### 增量验证策略

为缩短每次推进时间并减少无效日志，默认只运行受影响测试目标、一个真实数据
样本和 3～5 个关键 API 契约；输出仅保留汇总及失败项。只有修改共享传输、缓存、
公式解析器公共语法、API schema、打包流程，或准备阶段性发布时，才运行完整
CTest 和全 API 契约。纯文档或证据补充不启动服务回归。
