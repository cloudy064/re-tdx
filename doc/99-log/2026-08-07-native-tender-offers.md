# 要约收购事件纯 C++ 固定化

## 目标

在普通 A 股公式已无非 L2 解释器缺口、当前安装也没有可读 TPool 池定义后，
继续从尚未下载的公开 JSN 模板中寻找高价值、字段和单位都能由客户端配置闭合的
功能。本轮选择 `func_yysg101_1.jsn` 的要约收购主表，不涉及 L2。

## 发现与字段证据

对 20 个此前缺样本的静态模板执行只探测，16 个返回非空资源。其中
`list/func_yysg101_1.jsn` 为 86,562 字节；确认下载后的 MD5 为
`19acedfd4cd5f7a1b1b56f40818814f4`。原始表有 169 行、137 只证券，覆盖深、沪、
北市场。状态分布为：

- 要约完成 144 行；
- 要约失败 19 行；
- 要约准备中 3 行；
- 要约进行中 2 行；
- 要约暂停中 1 行。

安装目录 `T0002/cloud_cfg/func_yysg101.cfg` 是 GBK XML，明确给出了全部字段
语义和单位：`date/sgr/jd/gflx` 分别为最新公告日、收购人、最新转让进度和股份
类型；`njg/ngs/nbl/nzzj` 为拟要约价格、万股、总股本百分比和万元；
`qsr/zzr/sjgs/sjbl/ghr/ts/md` 为起止日、实际万股、实际比例、股份过户日、
是否退市和要约目的。因此 C++ 输出把万股乘 10,000 归一为股、万元乘 10,000
归一为元，同时保留原值字段和完整 `raw` 证据。

最新样本为 `SH600491`：2026-08-05 公告，要约进行中，价格 1.25 元，拟要约
9,178.60 万股、占总股本 6.00%，拟用资金 11,473.25 万元，要约窗口为
2026-07-28 至 2026-08-26。`BJ920808` 的存在同时验证了北京市场号 2。

## 实现

新增纯 C++ `market tender-offers`：

- 支持深/沪/北市场、证券、状态、公告日期和全文过滤；
- 支持公告日、起止日、价格、拟定/实际股数与比例、资金、完成率和代码排序；
- 保留同一证券的多次历史事件，不按股票错误合并；
- 将准备、进行、暂停、完成、失败归一为稳定英文类别，同时保留中文原状态；
- 计算 `actual_to_planned_pct`，空的实际结果保持 `null`；
- 上游刷新失败且进程内已有完整缓存时返回 `stale-cache`，冷缓存仍严格失败。

固定 API 为 `/api/v1/market/tender-offers`。Svelte 数据中心新增全市场“要约收购”
页，个股工作台“筹码股东”分组新增单票历史页签。功能目录和 OpenAPI 同步注册，
没有 Python 转发。
