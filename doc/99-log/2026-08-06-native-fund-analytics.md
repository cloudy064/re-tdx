# 基金风险、能力与仓位模型纯 C++ 固定化

## 请求族

六份 `T0002/cloud_cfg` XML 在
`HQServ.hq_nlp_risk_return / module_risk_return.dll` 下定义十条普通 JSON
TQLEX 请求：

| 视图 | ReqId | 业务 |
| --- | --- | --- |
| `risk` / `risk-history` | `500030/500031` | 风险收益主表与逐日基准对比 |
| `monthly-risk` / `monthly-history` | `500032/500033` | 月度风险主表与逐月基准对比 |
| `selection-skill` | `500035` | C-L/T-M/H-M 择时选股能力 |
| `holdings-stability` | `500055` | 区间换手、集中度和稳定性 |
| `holding-industries` / `holding-history` | `500056/500057` | 行业平均持仓和报告期仓位 |
| `position-estimates` | `500060` | 单基金报告/估算仓位 |
| `market-position-history` | `500062` | 股票型、偏股混合型与市场仓位序列 |

新增纯 C++ `market fund-analytics` 和固定只读
`/api/v1/market/fund-analytics`。默认投资风格严格沿用客户端 `005001` 普通
股票型；基金规模、成立年限、三种基准、起止日期、无风险利率和基金代码均为
类型化参数。明细视图不要求先从主表选中基金，直接以六位基金代码请求。

## 分页和当前规模

风险宽表以页长 200 请求时真实返回 ErrorCode 2“输出缓冲区不足”；页长 50
可稳定完成 24 页并得到 1,188 行。因此固定工具内建安全页长 50，默认自动
翻页，`--first-page`/`first_page=1` 才返回客户端首屏。当前结果：

- 风险、月度风险、择时选股和持仓稳定性均为 1,188 行/1,188 只唯一基金；
- `000711` 最近三个月日明细 51 点，最近三年月明细 37 点；
- 最新完整报告区间内行业持仓 6 行、报告期仓位 9 行；
- 单基金仓位估算 1,131 行/1,131 只唯一基金；
- 全市场仓位历史最近一年 242 点。

仓位估算当天可能先返回 `reportDate/estimateDate=0` 的全零占位。工具在用户
没有指定日期时先做一页探测，最多向前检查十天，再对最近可用日期完整翻页。
2026-08-06 当前回退至 2026-08-05；南方中小盘成长 `000326` 的报告仓位
94.0543%、估算仓位 87.5364%，相差 -6.5179 个百分点。当日股票型、偏股
混合型和合并市场估算仓位分别为 87.56%、83.91% 和 84.48%。

## 单位审计

所有 `_pct` 字段输出百分点；比例、份额和市值保留上游原单位。月度明细是
特殊混合编码：`return_start/return_last/bp_return_*` 是比率，需乘 100；
`ei_start/ei_last` 已是百分点。`000711` 2026-08 的基金月收益从 0.0414 转为
4.14%，基准从 0.0120 转为 1.20%，超额保持 2.9332 个百分点。逐日明细的
同名字段本身已经是百分点，不做重复缩放。

基金市场号 33 是该服务的基金业务身份，接口使用 `FUND:<code>`，不会把它
误映射成沪深证券市场。`recoverDate/recoverdayNum=-1` 转换为空值和
`recovered=false`；基金经理字符串拆为数组。
