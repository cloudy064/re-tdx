# 因子研究中心纯 C++ 固定化

当前安装的 `T0002/cloud_cfg/gp_gz_fsld.xml` 把因子研究页定义为同一
`HQServ.hq_nlp_factor` 入口、`mod_Factor.dll` 模块下的六条普通 JSON 请求：

| ReqId | 固定视图 | 客户端页大小 | 业务语义 |
| --- | --- | ---: | --- |
| `200626` | `catalog` | 100 | 33 个普通因子、方向、公式族及 120 日回测 |
| `200636` | `members` | 200 | 以普通因子 `ID` 展开股票 |
| `200646` | `dashboard` | 200 | 股票入选因子总数及因子名称 |
| `200650` | `patterns` | 100 | 57 个形态因子及 120 日回测 |
| `200651` | `pattern-members` | 200 | 以形态因子 `ID` 展开股票 |
| `200660` | `intraday-radar` | 1000 | 分时入选因子、时间、入选后涨幅和安全分 |

新增纯 C++ `market factors` 与固定只读
`/api/v1/market/factors`。目录统一输出今日/近五日收益，以及 120 日窗口内
入选后 1/3/5/10/20/60 日收益、最大回撤和夏普比值；百分数字段保持通达信
返回的百分点单位。普通因子的 `BullBear=0/1` 显式映射为 bullish/bearish，
不再让调用方猜枚举。

明细分页存在一个原客户端没有展示出来的重要边界。XML 的普通/形态明细和
因子看板固定只请求第一页 200 条，但服务器继续接受 `Page=1..N`：因子 24
“净利润同比增长”第一页、第二页都正好 200 条，完整翻页最终得到 2,524 只；
因子看板第一页以外也有记录，完整集合为 5,186 只，信号数从 10 递减到 1。
因此固定工具默认自动翻页，`--first-page`/`first_page=1` 才复现客户端首屏。
响应同时保留客户端页大小、是否全量、原始行数和截断状态。

真实复验还得到：普通目录 33 行，形态目录 57 行，形态因子 49“十字星”
115 只；分时雷达当前 462 条，安全分最小/最大 61/100，证明 XML 文案中的
“安全分大于 60”已由服务端落实，而不是客户端再过滤。分时规则按客户端原文
记录为“量价齐升”和“趋势拐点”，接口明确 `investment_signal=false`。

普通因子明细真实只有代码、名称、市场、涨幅、现价五列，形态明细另有
10 日涨幅；成交量额、市值、PE、行业等是原网格的 `syscol` 客户端行情列，
不是因子服务字段。工具的 `--quotes`/`quotes=1` 会显式调用公开 `0x054C`
补齐 L1 快照。因子 1“60日新高”实测 46/46 只全部匹配成功；补全失败只产生
警告，不否定原始因子信号。

真实请求和规范化证据保存在 `output/probes/tqlex-2006*.json` 与
`output/probes/factors-*.json`。新增规范化单元测试覆盖目录回测、市场身份、
普通/形态成分、因子标签拆分和分时安全分。临时 HTTP 服务验证功能目录增至
82，目录返回 33，因子 24 返回 2,524；同参数第二次请求命中 60 秒内存缓存，
不存在的因子 ID 返回 HTTP 400，而不是伪造空成功。

后续增加 `security` 反查视图：先完整读取 `200646`，按市场和六位代码精确
定位股票，再以因子名称连接 `200626`。平安银行当前安全分 95，命中多头排列、
大盘股、净利润同比增长、营收同比增长、现金流大于利润、高股息和高资产
负债率 7 个普通因子，目录连接 7/7；不存在于看板的证券返回显式空关系，
不报“所选股票缺失”错误。形态因子没有同类反向请求，仍只支持因子→股票。

审计也确认普通目录的 `formulaName + pos` 是 `mod_Factor.dll` 服务端因子族，
不是 TCalc 公式库键。名称相近的公式存在谓词差异，因此响应标记
`tcalc_formula_equivalence=false`，不会把本地解释器结果冒充服务端命中原因。

全量 CTest 增至 33 项并全部通过。阶段性服务验证中，因子 24 冷请求约
3.07 秒，随后同参数完整 2,524 行缓存响应约 281 ms，客户端兼容首屏返回
200 行；平安银行普通因子反查全冷约 7.94 秒，缓存命中约 18.3 ms；缺失
市场参数返回 HTTP 400。最终部署状态见本文末尾。

## 完整关系矩阵、广度和快照

继续新增 `standard-matrix`、`pattern-matrix`、`overview` 三个派生视图。
矩阵没有猜测服务端反向入口：普通矩阵对 `200626` 的 33 个 ID 各执行一次
完整 `200636`，形态矩阵对 `200650` 的 57 个 ID 各执行一次完整 `200651`。
当前普通矩阵 33/33 成功、16,863 条关系、紧凑 JSON 约 3.89 MB；形态矩阵
57/57 成功、4,825 条关系、3,032 只唯一证券、16 个当前空因子，紧凑 JSON
约 1.32 MB。形态矩阵约 16 秒完成；`security --include-patterns` 复用它建立
反向索引，平安银行除 7 个普通因子外又命中强势类“龙腾四海”，并保留其
`200651` 现价和十日涨幅成员行。

`overview` 基于 5,186 行完整 `200646` 看板计算当前覆盖率、平均安全分、
平均当日/十日涨幅、上涨占比、信号数分布和因子共现。当前生成 365 组实际
共现；覆盖最高的营收同比增长为 3,149 只（60.72%），净利润同比增长为
2,670 只。安全分分布为低于 60 共 459、60—79 共 956、80—100 共 3,771；
没有空安全分。最常见共现是净利润同比增长+营收同比增长，共 2,076 只，
Jaccard 55.46%。

广度结果同时与普通矩阵对账，证明两条上游视图存在真实口径差异，而非分页
重复：`200646` 当前 5,186 行且证券 ID 5,186 个唯一；普通矩阵 33/33 成功，
但仅 6 个因子的两侧集合完全一致，27 个不一致。净利润同比增长为看板
2,670、直接 2,524、交集 2,524、看板独有 146、直接独有 0；用 200/1000
两种页大小完整请求仍均为 2,524，下一页为空。济安线金叉还同时出现看板
独有 16、直接独有 9。接口不裁决哪一侧“更真”，而是返回两者、交集、独有
集合计数与 Jaccard，避免把聚合看板错误当成直接成分接口。

新增 `diff_factor_documents` 和 `update_factor_snapshot`。目录按因子 ID、成员/
看板按证券 ID、分时雷达按“证券+因子+入选时间”、矩阵/广度按因子 ID 建立
稳定身份，输出新增、移出、字段变化和未变化。真实目录连续快照为 33 个稳定
身份、0 增删改、33 未变化。被 `limit` 截断或 `availability=partial` 的结果
会拒绝保存；状态文件使用现有原子写入实现，`--snapshot` 与输出文件也禁止
使用同一路径。
