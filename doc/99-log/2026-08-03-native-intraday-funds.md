# 分时段主力资金纯 C++ 聚合与个股接入

## 目标

把旧 `update_tdx_intraday_funds.py` 的 `200340→200341` 聚合迁入统一
`tdx-tool.exe`，同时解决单票反查如果全量扫描 30 个行业会过慢的问题。
运行时不调用 Python，也不读取旧脚本生成的 JSON。

## 关键发现

`200340` 返回的 30 个一级行业代码就是本地 `research-industry` 树的一级
`block_code`。例如平安银行在本地三级链为 `X50→X5001→X500102`，一级
`X50` 的板块代码是 `881385`，与 PBRPC 的“银行”行业完全一致。

因此单票路径可以固定为：

1. 从常驻本地板块索引定位股票的一级研究行业；
2. 请求 `200340` 市场/行业总表；
3. 只用 `code_hy/market_hy` 请求一个 `200341` 行业明细；
4. 从成分记录中取出目标股票并同时保留行业汇总。

这把单票明细请求从最多 30 次降为 1 次；总表和各行业明细另有 15 秒内存
缓存。缓存仅避免短时间重复请求，不把盘后历史产物伪装成实时数据。

## 实现

- 新增 `native/include/tdx/funds.hpp` 与 `native/src/funds.cpp`；
- 新增 `market funds` 子命令：默认市场总表，支持 `--market/--code`、
  `--industry 881xxx` 和 `--all-industries`；
- 新增固定只读 API `/api/v1/market/funds`；
- 规范化今日、9:35 前、10:30 前、10:30—11:30、13:00—14:00、
  14:00—15:00、尾盘 30 分钟七段净流入、成交额、主力占比、涨幅、成交量
  和相对量；股票明细成交量按客户端 XML 证据完成股/手单位换算；
- 全量模式同时生成行业→股票和股票→行业索引；
- Svelte 个股“更多”抽屉新增“分时资金”页签，仅打开时加载；页面可见时
  每 15 秒检查更新，并可强制刷新。

## 边界

- 这是公开 PBRPC 业务数据，不是 Level2 逐笔或委托队列；
- `881xxx` 使用研究行业一级分类，不能与通达信行业 `880xxx` 叶子节点混用；
- 全量模式有 30 次行业请求，适合命令行导出；网页单票模式始终只请求对应
  的一个行业。

## 2026-08-05：`RpcID -1` 间歇故障记录

个股工作台查看 `SH600521 华海药业` 的分时资金时，曾出现：

```text
PBRPC server rejected request with RpcID -1
```

同一生产接口随后恢复正常，能够稳定解析到一级研究行业
`881230 医药医疗`，目标股票也存在于行业明细中。因此该问题不是市场参数、
证券代码、本地行业映射或 `200341` 组合键错误，而是公开 TQLEX/PBRPC
端点在初始握手阶段偶发返回拒绝值。

有限强制刷新复现结果：

- 第一组 8 次请求中 7 次成功、1 次失败，失败出现在第 7 次；
- 第二组连续请求在 3 次成功后，第 4 次再次返回相同错误；
- 成功请求通常约 2.0—2.2 秒，失败响应约 1.2 秒；
- 失败 HTTP 响应为 `bad_request`，服务端原始诊断保持为上述 `RpcID -1`；
- 停止强制刷新后的一次普通校验也再次返回相同 400，但服务进程保持运行；
- 当前页面每 15 秒轮询，后端缓存 TTL 也是 15 秒，轮询命中 TTL 边界时会
  重新执行 `200340→200341`，因而会放大上游偶发拒绝的可见概率。

本次按“恢复后先记录、暂缓修改”处理：没有部署重试或缓存兜底，也没有重启
生产服务。若再次出现，优先按以下顺序修复并验收：

1. 在 C++ PBRPC 层记录失败发生于 `200340` 还是 `200341`、请求轮次和耗时；
2. 仅对尚未建立会话的首次 `RpcID=-1` 做一次新握手重试，不重放已经开始的
   分段传输；
3. 两次握手均失败时，最多回退 5 分钟内的最近成功缓存，并在响应中明确标记
   `stale`，避免把旧数据伪装成实时数据；
4. 网页静默轮询改为去重，并评估把间隔提高到 30 秒；
5. 用 `SH600521` 做至少 20 次强制刷新回归，同时确认手工刷新与自动轮询并发
   时不会清空已有数据。
