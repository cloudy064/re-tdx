# TCalc 源码解释器、选股扫描与专家回测

> 日期：2026-08-05。实现位于 `native/src/formula_engine.cpp`、
> `formula_scan.cpp` 和 `formula_backtest.cpp`；运行时不加载 DLL，也不调用 Python。

## 结论

读取。引擎支持赋值/输出、参数、序列算术和逻辑、条件表达式、绘图后缀隔离，
以及 `REF/MA/EMA/EXPMEMA/SMA/SUM/HHV/LLV/LOWRANGE/TOPRANGE/WINNER/COST/COUNT/CROSS/STD/AVEDEV`、
连续条件、回归、加权均线和常见选股函数。

语义的 L2、特色交易值和跨指标序列不会伪造为零。

## 工具闭环

- `formulas analyze`：输出每条公式的函数、输出、行情依赖、外部依赖、绘图
  指令、未来函数和两级可执行状态。
- `formulas audit`：在一组 K 线上依次执行全库候选，不保留庞大点数组，只汇总
  运行错误、空输出和有效末值；`--with-context` 会一次装配共享只读上下文。
- `formulas evaluate`：从公式库选择任意恢复正文，合并 DLL 参数默认值后运行。
- `formulas scan`：接受本地 K 线包、显式证券列表或服务端全 A 股目录；支持
  并发抓取、磁盘缓存、增量刷新和最近 N 根信号检查。
- `formulas backtest`：消费专家公式的 `ENTERLONG/EXITLONG`，采用“收盘确认、
  下一根开盘执行”，输出佣金、滑点、收益、最大回撤、胜率、交易和权益曲线。
- API 新增 `/api/v1/formulas/coverage`、`evaluate` 和 `backtest`；Svelte 公式页
  展示可执行状态，可选择恢复公式计算，并可直接启动专家回测。

### `LOWRANGE/TOPRANGE` 原生边界

官方函数表说明两者用于判断当前值是近多少周期的最小/最大值。为确认计数边界，
又从当前 `TCalc.dll.i64` 追到 `TOPRANGE=0x10007170`、
`LOWRANGE=0x100072D0`：返回值是不含当前柱、向前连续满足严格更低/更高的柱数；
差值采用 `1e-5` 容差，遇到相等或容差内值停止，首个有效值返回 0。实现按该分支
逐项复刻并加入相等值、容差和序列起点测试，由此新增解锁“回补跳空向上缺口”与
“鸳鸯底”两条条件选股公式。官方说明见
[通达信公式函数列表](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)。

### `WINNER/COST` 原生筹码递推

从当前 `TCalc.dll.i64` 恢复到 `WINNER=0x10020580`、`COST=0x1001F0A0`。
两者按全段最高/最低价建立 0.01 元网格，每根日线先以 `1-VOL/CAPITAL` 衰减
旧筹码，再把本日成交量按最低价—中间价—最高价的三角权重加入网格；
`WINNER` 对目标价以下筹码求占比，`COST` 对累计筹码求指定百分位价格。
实现还保留 DLL 的浮点阈值、端点舍入和 5,000 万格次工作量上限。

DLL 通过宿主回调类型 103 请求按交易日排列的流通股本。本工具以 `0x0010`
当前财务作校验，并从 `0x000F` 股本变迁的变更前/后流通股恢复逐日 `CAPITAL`
（单位为手），不把最新股本常量反灌整段历史。由此新增解锁 `CYD/CYQKL/ZJTJ/
SCR/ASR` 五个技术公式和 `COSTXG/PRD/PRX/ASRD/ASRX/C120` 六个选股公式。
平安银行 800 根日线的 302 条上下文公式均通过运行体检；官方函数表也明确
`WINNER/COST` 只适用于日线，因此解释器对分钟、周线和月线显式拒绝。

### `BUYVOL/SELLVOL` 即时内外盘

官方函数表确认 `SELLVOL=DYNAINFO(22)=内盘`、`BUYVOL=DYNAINFO(23)=外盘`。
`0x054C` 快照已有同单位的 `inside_dish/outer_disc`（手），因此分析器将两个
符号标为快照上下文依赖，执行器按常量序列绑定当前盘面。由此新增解锁条件选股
`B005`（盘中活跃低价股），含上下文覆盖升至 303，平安银行全库审计仍为
303/303 且无空输出。

### `FINANCE(43/44)` 最新财报同比

官方函数表把 `FINANCE(43/44)` 定义为最近一期净利润/营业收入同比，官方专业
财务字段表又明确 `FN184=净利润增长率(%)`、`FN183=营业收入增长率(%)`。
上下文因此直接传递专业财务包的官方百分比，不用本工具重算；这会原样保留负
基数、零值和通达信异常口径。平安银行 2026Q1 实测分别为 `3.03%/4.65%`，
且 `FN230/FN232` 与 `0x0010` 的收入、归母净利润仅有 float32 舍入差。

由此解锁 `A006`（PEG 选股）和 `A010`（轻资产小型成长股），条件选股覆盖升至
`105/107`，总覆盖升至 305；800 根平安银行日线的 305 条候选全部通过且都有
数值末值。该上下文是“最新可用报告期常量”，只用于当前判断和链路验证，不能
冒充逐历史时点、无前视偏差的财务序列。字段定义见
[官方专业财务数据](https://help.tdx.com.cn/quant/docs/markdown/TdxQuant.md/mindoc-1h10m001ic888.html)
和[官方函数列表](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)。

### `FINANCE(90/91)` 方案事件天数

系统公式 `A012` 使用 `DNUM>0 && DNUM<N`，默认 `N=5`。结合函数表的“距今天数”
定义，事件计数按当天 `1`、昨天 `2`、无事件 `0` 实现；这也保证当天刚公告的
方案不会被系统公式排除。回购取 `list/func_qxfa104_1.jsn` 的董事会通过日
`ggrq`，股权激励取 `list/func_qxfa401_1.jsn` 的公告日 `ggrq`；同证券取不晚于
本地今天的最新日期，明确忽略资源中的未来排期。两张主表采用 5 分钟进程缓存，
不会在全市场扫描中逐股重复下载。

2026-08-05 的深市 `002028` 是真实边界样本：`FINANCE(91)=1`，A012 最新值为
`1`。加入该上下文后，条件选股达到 `106/107`，整库上下文覆盖与平安银行运行
审计均为 `306/306`。

### `FINANCE(88)` 宿主 tipinfo 日期

TCalc 的 `sub_10026B20` 对 `FINANCE(80..91)` 统一请求宿主类型 `0xA3`；88
读取偏移 244 的日期且只接受正方向，负方向属于 89。TdxW 的 `sub_60FFF0`
把证券主记录 `+587` 复制到该偏移，方向取 `+591`，而 `sub_4F5B60` 又明确
从 `hq_cache/tipinfo.dat` 第 18/19 字段加载两者。该表位于可用 `0x06B9`
更新的 `zhb.zip`，所以原生 C++ 下载器现会一并安全解压和索引。

2026-08-05 在线包有 5,615 条证券记录，但北向日期/方向非空计数为 0；A013
因此按通达信当前宿主语义得到 `FINANCE(88)=0`，没有采用只含 2024-08-16
单日的 `func_hsgt205` 反推历史。加入这一精确空值语义后，条件选股达到
`107/107`，整库上下文覆盖及平安银行 800 根日线运行审计达到 `307/307`。

### `FINANCE(48/52)` 标的资格

TCalc 的 `sub_10026B20` 对两字段请求宿主类型 105：`FINANCE(52)` 读取返回缓冲
`+39`，`FINANCE(48)` 读取 `+67`。TdxW 的 `sub_60E580` 显示前者来自证券主
记录 `+521`，后者是 `+522 || +523`；`sub_5A6680` 又分别调用
`sub_5EB820/sub_5EBA80/sub_5EBB30` 填充三个字节。最终 `sub_607490 ->
sub_5EADA0` 证明三个有序成员数组都由 `T0002/hq_cache/spblock.dat` 读取：

- `FINANCE(52)`：`#融资融券`；
- `FINANCE(48)`：`#沪港通SH` 与 `#深港通SZ` 的并集。

纯 C++ 解析器按文件修改时间和长度缓存该资源；本机当前三组分别为 4,432、
1,900、2,062 个成员。平安银行实测两值均为 1，“北上资金”和“两融资金”
各返回 800 根结果并具有有效末值。加入后技术指标上下文覆盖从 161 增至 163，
整库覆盖及运行审计达到 `309/309`，错误、全空输出和空末值均为 0。

### `DYNAINFO(28/29)` 即时买卖笼子价

TCalc 的通用 `DYNAINFO` 求值器 `sub_10028670` 在 28、29 分支请求宿主数据
类型 121，selector 固定为 198；返回缓冲 `+4/+8` 分别成为 28/29。TdxW 的
case 121 又调用 `sub_93AC50/sub_93AFD0`：买价上限先取卖一，卖价下限先取
买一，缺失时依次回退另一侧、现价和昨收；普通证券按 `102%/98%`，北交所按
`105%/95%`，股票再叠加至少 10 个价位，最后分别以涨停/跌停价截断。

纯 C++ 实现复用了 `0x0547` 五档记录，盘口公式只发一次请求，不再重复请求
`0x054C` 快照。平安银行当前卖一 `11.25`、买一 `11.24` 时，恢复结果为
`DYNAINFO(28)=11.48`、`DYNAINFO(29)=11.02`；真实 `FSCAGE` 在 800 根 1 分钟线
上通过，技术指标覆盖从 163 增至 164，总覆盖及日线全库体检达到 `310/310`。
当前普通、创业板、科创板和北交所的板级涨跌停边界已接入；ST 和上市初期
无涨跌幅限制等特殊状态仍依赖宿主证券标志，后续需继续恢复该标志，不能把
板级边界称为这些特殊证券的精确涨跌停价。

### `TOTALFZNUM/HOUR/MINUTE/REFDATE` 会话与日期内建量

TCalc 注册表把 `TOTALFZNUM` 指向 `sub_100174A0`。它请求宿主 type 105，读取
四组成对的交易时段并计算 `Σ(结束分钟-开始分钟)`。TdxW case 105 对 set-code
0/1/2 返回相同默认时段：`570–690`、`780–900` 和两个 `900–900` 空段，即
沪、深、北市场均为 240 分钟。由此解锁 `VOL-TDX/AMO-TDX` 两个虚拟量额公式。

`HOUR/MINUTE` 分别由 `sub_10006440/sub_10006480` 逐根读取 35 字节 K 线记录
偏移 `+4/+5`。`REFDATE` 的 `sub_100074F0` 则只取第二参数末值作为目标日期，
从末根向前查找首个 `bar_date<=target`，再把第一参数在该位置的值广播至全部
输出柱。实现这些边界后，“参考结算价”和“买卖区间”也进入原生解释器。

真实验证包括 800 根日线的虚拟成交量/成交额和买卖区间，以及 800 根 1 分钟
线的参考结算价。覆盖从 `214/310` 推进到 `216/314`（直接/上下文口径）；
其中技术指标为 `117/168`。

### 跨证券 OHLCVA 与 type-120 行业指数

`date|time` 对齐，真实解锁 `SCAMO`。行业侧恢复
`sub_10025890/sub_10025B60/sub_10025E30/sub_10026100` 等求值器和 TdxW
type 120 的 `880xxx/881xxx` 选择，`HYDB` 可由个股直接定位本地行业并读取行业

[专项记录](2026-08-05-native-cross-security-industry-series.md)。

### 文本符号与 type-163 封板状态

`HQCRBK` 已确认读取宿主 type 122 的背景标志；`DYBLOCK` 从 type 120 返回结构
`+155` 读取内置 32 项地域表，`GNBLOCK` 通过 command 8 的概念归属返回。
`CON2STR/STRCAT` 是 TCalc 字符串池操作；数值解释器对其使用无害占位，并把
行业、地域、概念真实文本及来源保存在上下文元数据。

`DYNAINFO(88)` 虽被帮助文字称为“实时封单额”，当前 TdxW case 163 的 `+384`
实际只在盘口封死涨停时写入涨停幅度，否则为 0；系统“上榜标注”恰好只判断
其是否大于 0。恢复这些依赖后，覆盖由 `216/317` 推进到 `217/319`，技术指标
为 `118/173`；全库上下文审计 `319/319` 无错误。详见
[专项记录](2026-08-05-native-formula-text-dynainfo88.md)。

## 明确边界

`BACKSET/REFX/REFXV/XMA/ZIG` 等前视函数仍标记为未来函数，不会进入普通
扫描和回测。`L2_AMO/SIGNALS_QS` 等仍需授权会话或尚未确认的数据函数保留
真实依赖，不以估算数据冒充。`GPJYVALUE/BKJYVALUE/SCJYVALUE` 已按官方
13 字节记录和日期对齐；自动 `FINVALUE` 上下文当前明确使用“最新可用报告期
常量”，还不能当作无未来信息的历史财务序列用于回测。
