# JSN 增量能力发现

## 目标

在 340 个已下载 JSN 已全部类型化之后，继续解决“客户端以后下载了什么新资源、
已有资源字段是否变化、动态文件名里的真实键是什么”这类时间维度问题。实现保持
纯 C++，不依赖 Python，不猜测没有非空样本的业务 schema。

## 实现

新增统一子命令 `recon jsn-discovery`：

- 为每个具体 `.jsn` 保存 SHA-256、字节数、分组、行数和字段集合；
- 对比可选基线，分类 `added/changed/removed/unchanged/unbaselined`；
- 输出新增和移除字段，并对每列最多抽样 64 个值，统计非空、数值、整数、
  日期、URL、HTML 特征和三个短样本；
- 将具体路径重新匹配到 XML/CFG/内置动态模板，提取 `SC/ZQDM` 等占位键；
- 联合现有类型化命令和 API 绑定，对新增、未知、只有通用入口、证券相关及
  新字段给出优先级，便于下一轮只处理真实高信息增益样本。

动态模板匹配同时补充了期货市场号 `47`。真实文件 `qhtj2/47IFL8.jsn` 现可
正确解释为 `SC=47`、`ZQDM=IFL8`，而不是无法识别或把市场号截成一位。

## API 与网页

新增只读 GET `/api/v1/jsn/discovery?top=100`。服务端缓存最近一次完整扫描，
`refresh=1`、下载 JSN 或捕获基线会使缓存失效。生产样本首次扫描约 8.6 秒，
缓存响应约 0.25 秒。

捕获基线是唯一新增写操作，必须同时满足：

```text
POST /api/v1/jsn/discovery?action=capture
X-TDX-Action: jsn-discovery-baseline
```

缺少确认头实测返回 HTTP 405。Svelte 的 JSN 资源页增加“增量能力发现”表，展示
状态、类型化覆盖、字段变化与优先分；点击变化资源会联动现有资源检索，按钮可将
当前扫描设为新基线。
