# TCalc 公式正文恢复与原生指标 v4

## 本轮结果

- 确认 `tag_INDEXINFO + 5052` 为系统公式正文绝对指针；
- 纯 C++ 离线导出器通过 PE `ImageBase/RVA` 关系恢复 361/379 条完整正文；
- 18 条受保护技术公式的指针为 0，明确返回不可用，不做邻近字符串猜配；
- `/api/v1/formulas` 支持按公式正文检索，Svelte 详情面板直接显示源码；
- 根据 DLL 中恢复的原文实现 `DMI/WVAD/EMV/CHO/ADTM/DKX`，稳定计算子集
  从 20 类增加至 26 类，引擎升级为 `tdx-native-compatible-v4`；
- TPool 兼容规则和网页指标选择器同步识别新增公式。

## 正文恢复证据

每条内置公式记录长度为 5072 字节。当前指纹版本中，偏移 `5052` 的 32 位值
是首选映像基址下的正文地址。例如 DMI：

```text
record index 33
source pointer 0x101156D0
image base     0x10000000
source RVA     0x001156D0
```

该 RVA 映射得到的正文包含 `MTR/DMP/DMM/PDI/MDI/ADX/ADXR` 全部表达式。
四类公式的恢复结果为：

| 类型 | 总数 | 正文可用 | 正文受保护 |
| --- | ---: | ---: | ---: |
| 技术指标 | 222 | 204 | 18 |
| 条件选股 | 107 | 107 | 0 |
| 专家系统 | 15 | 15 | 0 |
| 五彩 K 线 | 35 | 35 | 0 |
| 合计 | 379 | 361 | 18 |

导出结果保存在 `output/tcalc-all-formulas-with-source.json`。JSON schema v3
为每条公式增加 `source_text_available/source_rva/source_text`，CSV 同步增加
这些列。

## 新增指标的原文差异

- `DMI` 明确采用 N 周期 `SUM`，不是 Wilder 或 `EXPMEMA` 变体；
- `WVAD` 原文末尾包含 `/10000`，计算器保留该缩放；
- `EMV` 原文先计算 `MA(VOL,N)/VOL`，再进行两层 N 周期均值；
- `CHO` 先对成交量加权项执行 `SUM(...,0)`，再计算 N1/N2 均值差；
- `ADTM` 对开盘价上涨、下跌和平盘分别走 DTM/DBM 分支；
- 当前版本 `DKX` 原文最后一项确为 `REF(MID,20)`，中间没有
  `REF(MID,19)`；原生实现按 DLL 原文保留这一版本特征。

`ASI` 的参数和输出槽可以恢复，但正文指针为 0，因此本轮没有把常见同名
算法冒充成该版本的已验证实现。

## 真实行情验证

平安银行 `SZ000001` 使用 120 根日线完成六项验证，2026-08-05 末值：

```text
DMI   PDI=30.448762, MDI=14.423080, ADX=71.702150, ADXR=77.006882
WVAD  WVAD=867.497274, MAWVAD=903.650909
EMV   EMV=0.183634, MAEMV=0.443249
CHO   CHO=25657.207012, MACHO=19097.637204
ADTM  ADTM=0.658537, MAADTM=0.580941
DKX   DKX=11.199206, MADKX=10.948009
```

`DMI/EMV/DKX` 另以两页共 200 根 30 分钟线验证，所有输出均完成预热并产生
有限数值。真实结果保存在 `output/formula-v4/`。

## 边界

- 公式正文恢复只接受当前已指纹识别的 TCalc 版本；未知哈希仍拒绝解析；
- 读取过程不加载 DLL，不调用 `InitMain`，也不触碰用户公式文件；
- 26 类计算器是逐项实现的兼容子集，不是通用公式解释器；
- 受保护公式只有明确的源码证据出现后才会进入稳定计算接口。
