> 迁入统一 C++ 工具、固定 API 和用户重新设计后的 Svelte 工作台。

## 客户端入口与资源

页面证据来自 `DZJYFX.sp`、`DZJY1.sp`、`DZJYYXSB.sp`、`HYYYB.sp`；
`func_dzjy101—1013.cfg` 给出以下已验证关系：

| 视图 | 主表 | 动态详情 |
| --- | --- | --- |
| 月度总览 | `list/func_dzjy101_1.jsn` | — |
| 近期成交 | `list/func_dzjy104_1.jsn` | `dzjy3/<市场号><代码>.jsn` |
| 意向申报 | `list/func_dzjy1012_1.jsn` | `dzjy13/<市场号><代码>.jsn` |
| 营业部排行 | `func_dzjy107/108/109/1010` | `yybph22401/2/3/4/<营业部ID>.jsn` |
| 月度行业 | `dzjy1/<YYYY-MM>.jsn` | `dzjy2/<月度行业隐藏键>.jsn` |

近期成交主表每只证券仅保留一条当前代表记录，并不是完整逐笔表；同票历史
必须继续读取 `dzjy3`。意向历史的重复行可能代表上游实际申报，原样保留，
不按日期或价格擅自去重。

## 关联键和单位

- 深圳、上海、北京规范市场号为 `0/1/2`。客户端主表中的北交所原始值
  `44` 只用于识别，动态路径必须转换为 `2`；`BJ920078` 的有效资源是
  `dzjy3/2920078.jsn`，`dzjy3/920078.jsn` 不存在。
- 行业详情不能用页面名称拼接。先读取 `dzjy1/<月份>`，再使用其中
  `$ZQDM` 返回的 `YYYY-MM+880xxx` 隐藏键读取 `dzjy2`。
- 营业部明细命名空间随统计周期变化：`22401/22402/22403/22404` 分别对应
  近一月、近三月、近半年和近一年。
- 成交额、成交量和申报量主表单位为“万”，C++ 输出统一转换为元和股；
  营业部明细金额由成交价 × 万股 × 10,000 推导。

## 纯 C++ 实现

- 新增 `market block-trades`，支持 `trades`、`intentions`、`brokers`、
  `industries` 四个视图及单票、营业部、行业下钻。
- 新增固定只读接口 `/api/v1/market/block-trades`，不接受任意资源路径。
- 月度、近期成交和意向三张核心表复用同一 7709 连接及五分钟内存缓存；
  营业部只读取用户选择的周期，避免一次下载四张大表。
- 动态资源缓存十五分钟；不存在的详情也短时缓存为失败，不重复打主站。
- 新增协议级归一化测试，覆盖北交所 `44→2`、金额/数量单位、同日多笔、
  意向金额、行业隐藏键、营业部收益窗口和营业部明细金额。

## 网页接入

## 边界和下一步

这些资源是公开大宗交易分析，不等同于 Level2 逐笔委托或十档行情。动态
详情可能因股票/月份没有数据而缺失，此时 API 保留主表并单独返回
`detail_errors`。下一项优先闭合公司回购计划、实施进度与单票历史链。
